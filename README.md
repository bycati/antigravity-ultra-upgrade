## 先搞清楚：Antigravity 的“Ultra”到底指什么

Antigravity 本身不单独收费，它的使用额度直接挂在你订阅的 Google AI 套餐上。所以“升级 Ultra”实际是升级 Google AI 订阅，再把 Antigravity 里能用的额度跟着抬上去。

麻烦在于，这套套餐在 2026 年里改过好几轮：

- 年初还是简单的双档结构，Pro 之外只有一个 Ultra；
- 3 月 11 日官方公告改版：Pro 的日常用法被重新设计成以轻量的 Gemini Flash 为主，Gemini 3 Pro、Claude 这类高级模型改成**按周限额**，超出后可以按量购买 AI credit 继续用，有用户报告称超限严重时甚至被锁了七天；
- 5 月 I/O 上 Antigravity 2.0 发布，套餐又调了一次：新增中间档 AI Ultra（$100/月，额度约为 Pro 的 5 倍），顶配 Ultra 从 $250 降到 $200。

顺带一提，旧的 Gemini CLI 和 Code Assist 扩展已在 6 月 18 日停用，统一并入 Antigravity CLI。迁移本身不花钱，但额度消耗的手感和以前不太一样，原来按老 CLI 校准的用量习惯需要重新适应。

## Pro 和 Ultra 用起来差在哪

额度规则是最核心的差别。3 月改版之后，Pro 的日常任务由 Flash 承担，高级模型按周发额度。写日常代码、修小 bug，Flash 够用；但调试疑难问题、做架构级改动时，你真正需要的是高级模型，而它们恰恰是限额最紧的。很多 Pro 用户觉得“钱花了但别扭”，别扭就别扭在这——需要的时候用不上。

Ultra 档的卖点是把这些限制拿掉：按官方 3 月公告的说法，顶配 Ultra 下 Gemini 3 Pro、Claude Sonnet、Gemini Flash 都不再有周限额和 credit 上限，“数着次数干活”这件事从工作流里直接消失。

中间档 AI Ultra 走的是另一条路：不是完全无限，而是给到约 5 倍于 Pro 的额度，价格只有顶配一半。Antigravity 2.0 的主打功能就是并行编排，同时跑三四个 Agent 的消耗是串行的好几倍——如果你的工作流围绕并行展开，中间档很可能才是新的甜点位。

顶配还有一些专属配置：Manager View 能同时盯所有 Agent 的进度，Editor View 负责跟单个 Agent 对话；另外提供云端 Mac 算力，Windows 或 Linux 用户也能构建和测试 iOS 应用，构建时间接近本地 M3 MacBook Pro，通常 2-4 分钟。（这部分整理自 Antigravity Lab 4 月对当时 $249.99 档的介绍，现对应 $200 档。）

## 十月的新变量：Gemini 4 Argon 和 Ultra 订阅者

TestingCatalog 10 月初的报道值得单独拎出来说。Antigravity 应用里出现了新的 Ultra 升级标签和订阅入口，跳转链接的 UTM 参数里已经带着 `argon_model_selector` 的字样。结合 Google 9 月 30 日的公告，Argon 的开放顺序是：先给可信的网络安全防御者，然后是付费 API 客户和 Ultra 订阅者。换句话说，**Ultra 订阅者大概率会在第一批能在编程工具里用到 Argon 的人当中**。

Argon 目前在 Google 内部工作流中运行，官方给出的 DeepSWE v1.1 得分是 77.9%，这个基准考察的是更长时间的软件工程任务——方向上就是给 Antigravity 这类 Agent 工作流准备的。

同期被扒出来的还有三个原型：支持实时语音的 Concierge Agent、减少权限弹窗的 Auto mode、界面皮肤自定义。都还在开发中，没有发布时间表。

所以如果你的升级决定本来就在边缘，“能先用到 Argon”算一个加分项。但注意，出现升级标签不等于发布日期确定了，别为这个传闻单独掏钱。

## 该不该升：两个自测方法，加一个反方视角

### 方法一：记录撞限额的频率

Antigravity Lab 给的办法很土但有效——每次撞到限额，往日志里记一行，带上当时并行跑的 Agent 数：

bash
echo "$(date '+%m/%d %H:%M') hit-limit agents=2" >> ~/antigravity-usage.log


一两周后看结果：每周撞 0-1 次，留在 Pro；只在并行多的日子撞，看看这些日子出现得勤不勤，再决定要不要上 AI Ultra；几乎天天撞，直接升，持续饱和再考虑顶配。

### 方法二：算停工成本

撞限额不是等一会儿就完事，工作停下来的同时上下文也断了。按 Antigravity Lab 作者自己的估算，一次停工加恢复大约损失 30 分钟。拿“停工次数 × 30 分钟 × 你的时薪”跟差价比：时薪 $50 的话，顶配 Ultra（$200）每月只要省出 4 小时就回本；时薪 $75，两小时四十分钟左右。

### 反方视角：多数人其实用不满 Ultra

该听听另一边的声音。来自日本市场的用户反馈是，Pro 超限后的 credit 加购平均每月约 1,000-3,000 日元，加上月费总支出通常在 4,000-6,000 日元之间——只有当时 Ultra 定价（36,400 日元）的六分之一到九分之一。而且 Flash 的实际性能比很多人想象的能打，日常修复和常规编码基本够用。“限额不方便”和“真的需要无限量”是两回事，为前者付十倍以上的价钱不划算。

## 升级前，先把现有额度榨干

不管最后升不升，这几招都能明显降低消耗：

- **按任务配模型**。Antigravity 2.0 默认引擎是 Gemini 3.5 Flash，日常生成和重构完全够；只有真正费脑子的设计决策、疑难调试才切高档模型。全程开高档，等于同样的活几倍消耗。
- **把请求写具体**。“修一下这个函数”比“把这个函数改成三目运算：输入大于 0 返回 positive，等于 0 返回 zero，否则返回 negative”贵得多——模糊的提示词会产出你要扔掉的代码，扔掉的输出是最贵的支出。
- **缩小上下文**。用 `.antigravityignore` 排除 node_modules、构建产物、锁文件，只开当前任务相关的文件，用完的 session 及时关掉。上下文越大，烧得越快。Antigravity Lab 的实测记录是：一次复杂架构咨询 30-50 credit，一次长上下文重构 100-200 credit，三个 Agent 并行时消耗大约是单 Agent 的 3 倍。
- **轻任务甩给本地模型**。分类、格式化、短摘要这类活可以丢给本地跑的 Gemma 4，一个 credit 都不花。
- **错峰安排**。前半周和月中之前干重活，25 号以后只安排 PR 审查、测试验证这种读多写少的维护任务。

## 升级之后，怎么把多花的钱赚回来

Ultra 最大的红利是并行，但并行不是无脑多开。适合并行的：互相独立的组件更新、不同模块的 bug 修复、一边写实现一边生成测试、多语言文件翻译。老老实实串行的：动数据模型（牵一发动全身）、共享状态的逻辑、按顺序依赖的部署流程。

Antigravity Lab 的作者记录过两个案例。一个是用三个并行 Agent 迁移 3 万行的 Next.js 项目，串行估计要 3-4 天的活，实际 6 小时干完，外加 2 小时人工复核。另一个是多租户认证功能，前端 UI、后端接口、数据库 schema 和测试四个方向同时开工，4 小时收工，几乎零冲突。零冲突靠的不是运气，是开工前在 AGENTS.md 里把每个 Agent 的读写边界写死：前端只能碰 components，后端只能碰 api，types 目录两边都只读。

按他的说法，头两周会觉得“这不就是 Pro 加了几步操作”，到第三个月，把工作拆成并行任务会变成默认习惯，那时时间账才算得过来。这个说法不夸张，但有个前提：你得真的愿意照着“哪些活能拆开”去重新安排工作，而不是买完额度继续按老方式干。

## 常见问题

**Q：升级后 Antigravity 还显示旧的限额怎么办？**
多半是缓存。命令面板跑 "Antigravity: Clear Authentication Cache" 重新登录；不行就彻底退出重开，再到设置 → 账户里同步。

**Q：免费版能拿来正经开发吗？**
不建议。编辑器核心功能都能用，但额度顶得很低，连续委托几个 Agent 任务就可能用完当天额度。它更适合当作一到两周的评估窗口，顺便攒下自己的用量数据，正好给付费决策当依据。

**Q：Ultra 是真的无限量吗？**
按官方 3 月公告，顶配 Ultra 下各模型没有周限额和 credit 上限。但这套规则一年里已经改了三次，“无限”是当下的政策，不是写进合同的承诺，别按“永久无限”做长期预算。

**Q：现在买会不会马上被新价格背刺？**
说不准，顶配档上次调整还是降价。规则肯定还会动，但“按撞限额频率决策”这个方法不会过期——价格怎么变，照着自己的数据选就行。
